# 从零搭一个小 GPT

这是我们上课的"工地"。你写 `src/`，我出题、讲背景、批代码；`check.py` 给你即时反馈。

目标不是"跑通一个别人写好的 Transformer"，而是**每一行代码你都能说出它为什么在那里**。

---

## 我们怎么配合

一次只推进一讲，节奏固定：

1. 我讲这一块**在 GPT 里到底干什么**，以及需要的新概念（数学 → 对应到代码）。
2. 我给出一个小接口：要写哪几个函数，输入输出是什么形状。
3. 你写 `src/` 里对应的文件。
4. `python check.py <讲次>` 自测。没过就把**报错原文**发我 —— 我不会直接给你改好的代码，会先问你看到了什么。
5. 全部通过后，我问 2–3 个理解题，答得上来才进下一讲。

我给出的顺序是**可调整的**：你觉得某一段太慢或太快，直接说。

模型代码已可训练和生成。2026-11-04 按你的要求删除了旧训练结果及 24 条教学问答；目前没有可直接加载的旧权重。
接下来由你自行启动训练，数据准备、命令及调参顺序见 [训练指南](lessons/10-training-guide.md)。

## 几条约定

1. **自己写。** 卡住就问，我会给三级提示（思路 → 知识 → 伪代码），但不会先给代码。
2. **报错原文优先。** "不对" 这种描述我帮不上；把 `AssertionError` 那几行贴过来，或者把 traceback 贴过来。
3. **通过不等于懂。** 每讲结束我会追问，答不上来说明这一讲还得再看一眼 —— 这不是惩罚，是提前暴露问题比在 L09 组装模型时崩掉强。
4. **检查代码可以读。** 它写的就是"什么叫做对"，读它比读我说话更精确。但改它没有意义（期望值是哈希校验过的）。
