# 02B 补课 · 矩阵求导到底在求什么

> 你说"完全被矩阵求导搞晕了"。这不是你的问题——绝大多数教材在这个地方讲错了重点。
> 这份材料只讲一件事：**反向传播从来不需要"矩阵求导"，它只需要三条规则。**

---

## 一、先拆掉一个误会：雅可比不是我们在算的东西

对 `y = W x`（W 是 3×4，x 是 4 维）：

- `∂y/∂x` 在教材里叫雅可比矩阵，形状 3×4——**这个能写成矩阵**。
- `∂y/∂W` 呢？y 有 3 个分量，W 有 12 个元素，它是 3×3×4 的**三阶张量**。
  它不是矩阵，也没法塞进矩阵。你之所以"求不出来"，是因为它本来就不该那样求。

反向传播实际算的不是雅可比，而是 **VJP（向量-雅可比积）**：

> 已知上游梯度 `dY`（形状和 `y` 一样），直接算出 `dW`、`dx`。
> 全程只有矩阵乘、逐元素乘、求和 —— 没有高阶张量。

所以：**背"∂y/∂W = x"这类公式是没有意义的**。那些式子是把 VJP 的结论伪装成了导数。

---

## 二、只需要三条规则

整个课程（包括后面的注意力）的反向传播，只有这三条。

### 规则 1：矩阵乘

前向 `Y = A @ B`，已知 `dY`，则

```
dA = dY @ Bᵀ
dB = Aᵀ @ dY
```

就这一条。**记住"转置另一边"就够了**：要谁的梯度，就拿 dY 去乘"另一个"的转置，转置放在哪个位置由形状决定（这次形状是够用的，下面说为什么）。

所有线性层都是它的特例：

| 前向 | 把谁代进 A、B | dA | dB |
|---|---|---|---|
| `Y = X @ Wᵀ`（PyTorch 的 Linear） | A=X, B=Wᵀ | `dX = dY @ W` | `dWᵀ = Xᵀ @ dY` → `dW = dYᵀ @ X` |
| `Y = X @ W`（不转置的写法） | A=X, B=W | `dX = dY @ Wᵀ` | `dW = Xᵀ @ dY` |

**注意这两个 `dW` 不一样**，因为 W 在前向里的位置不同。这也说明：`dy/dW = x` 这种公式是错的——它至少少了转置和"另一边"。

### 规则 2：逐元素函数

前向 `Y = f(Z)`，f 逐元素作用（relu、sigmoid、exp、tanh……），则

```
dZ = dY ⊙ f'(Z)        # ⊙ 是逐元素乘
```

- `relu`：`f'(z) = 1 if z>0 else 0` → `dZ = dY * (Z > 0)`
- 没有矩阵、没有转置、没有耦合。因为每个输出只依赖一个输入。

### 规则 3：广播（这是 `db` 的来源）

前向里如果一个张量被**广播**成了更大的形状，反向就要**沿被广播的那几维求和**，把形状缩回去。

```python
Z = X @ W.T + b     # b: (H,)  广播成 (B,H)
```

`b` 的每一份都被用了 B 次，所以

```
db_h = Σ_b dZ[b,h]      →  db = dZ.sum(dim=0)
```

这就是为什么 `db = dY.sum(0)`，而不是 `db = dY`。**形状变小的地方，加法一定出现在反向。**

---

## 三、这三条从哪来？（标量展开法，30 秒能推完）

不用背，推一遍就懂了。以 `Y = X @ Wᵀ` 为例：

**第一步**：写出单个元素（标量形式）

```
y[b,c] = Σ_h x[b,h] * W[c,h]
```

**第二步**：对目标元素求偏导（其它项当常数）

`W[c,h]` 只通过 `y[b,c]`（对所有 b）影响 L，所以

```
∂L/∂W[c,h] = Σ_b (∂L/∂y[b,c]) * x[b,h]
           = Σ_b dY[b,c] * x[b,h]
```

**第三步**：把求和认成矩阵乘

`Σ_b dY[b,c] * x[b,h]` 是"dY 的第 c 列"和"x 的第 h 列"的点积 ——
这正是 `dYᵀ @ X` 的第 (c,h) 个元素。所以

```
dW = dYᵀ @ X
```

同理对 `x`：

```
∂L/∂x[b,h] = Σ_c dY[b,c] * W[c,h]   →  dX = dY @ W
```

**看出规律了吗**：求和的下标被"消掉"，留下的两个下标就是结果的下标——于是它必然是一次矩阵乘。
这套"下标求和 + 认出矩阵乘"的活，和你写 DP 时推转移式是同一种脑力。

## 四、形状检查：必要，但不充分

你说"根据形状判断左乘右乘、是否转置"——**作为排错手段很好用，但不能当作证明**。

反例：当 `H == C` 时，`dW` 的形状 `(C,H)` 和 `(H,C)` **完全一样**，写反了形状检查也发现不了。
而在注意力里，`n_heads * d_head == n_embd` 是常见配置，这类"方阵巧合"到处都是。

所以正确的用法是：

- 先用**规则**推出式子；
- 再用**形状**确认没写错；
- 最后用**数值差分**（2B 的检查 04/05 就是这么做的）兜底。

## 五、速查表

| 前向 | 反向（已知 dY） |
|---|---|
| `Y = A @ B` | `dA = dY @ Bᵀ`，`dB = Aᵀ @ dY` |
| `Y = A @ Bᵀ` | `dA = dY @ B`，`dB = dYᵀ @ A` |
| `Y = X + b`（b 被广播） | `dX = dY`，`db = dY.sum(dim=0)` |
| `Y = relu(Z)` | `dZ = dY * (Z > 0)` |
| `Y = exp(Z)` | `dZ = dY * exp(Z)` |
| `Y = Z.sum(dim=d, keepdim=True)` | `dZ = dY.expand_as(Z)`（反向是把求和"撒回去"） |
| `Y = Z / Z.sum(...)`（softmax） | 见下 |

softmax + 交叉熵合起来的结果特别漂亮：

```
dLogits = (softmax(logits) − onehot) / B
```

**别单独推 softmax 的雅可比**（那是 B×C×C 的三阶张量，非常恶心）。永远把 softmax 和交叉熵**合在一起**推，结果就是一个减法。

## 六、三个自测题（能答出来，这一讲才算真的过）

1. 把前向改成不带转置的 `Z = X @ W + b`（W 形状 `(D,H)`），那么 `dX`、`dW` 各是什么？
   用两条路径验证：规则 1 推一遍；再用 autograd 跑一遍对拍。
2. 为什么 `db` 是求和而不是直接赋值？如果 batch size 改成 1，`db` 会变成什么？
3. 若 `H == C`，你怎么发现自己的 `dW` 转置写反了？

第 1 题可以这样自己验：

```python
import torch
torch.manual_seed(0)
X = torch.randn(5, 3, dtype=torch.float64)
W = torch.randn(3, 4, dtype=torch.float64, requires_grad=True)
b = torch.randn(4, dtype=torch.float64, requires_grad=True)

Z = X @ W + b
Z.sum().backward()          # 假设上游梯度全是 1
print(W.grad)               # 和手推的 Xᵀ @ ones 比
```
