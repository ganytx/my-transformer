# 自己训练 Mini-GPT：数据、实验和调参

2026-11-04：旧权重、旧训练记录、24 条教学问答和教师的训练试跑产物已删除。你的实现、测试和 Alice 原始文本保留。本指南中的命令由你运行，教师不会代你启动训练。

## 1. 先决定模型要练什么

你已经完成 GPT 结构，但随机初始化的权重还没有语言能力。训练就是反复用真实的下一字符监督预测，通过梯度和 optimizer 调整权重。

- 用小说训练：目标是续写小说。
- 用 `User: ...\nAssistant: ...\n\n` 格式的问答训练：目标是根据问题续写回答。
- 先训练普通文本、再训练问答：后一步叫微调，仍然在预测下一字符。

也可以直接用问答文本从随机权重训练，但此时连拼写、语法都需要从这些数据中学。给小模型增加少量问答，不会自动得到通用聊天能力。第一目标宜定成一个范围明确的英文任务，再观察它对未见表达的表现。

## 2. 数据比盲目加步数更优先

训练集用来更新参数；验证集用来选择参数和训练时长；测试集留到方案确定后作最后检查。验证集参与调参以后，就不再是完全独立的最终测验。

准备数据时依次做：

1. 选定内容范围，检查实际问答质量、重复比例、问题和答案的长度。先人工读几十条。
2. 去重；同一问题的近似变体、同一篇文档或同一棵对话树放在同一个分组。
3. 固定随机种子，按分组切成训练/验证/测试，例如 90%/5%/5%。小数据集要保证验证题数量有意义，比例不是硬规定。先切分，后格式化、拼接。
4. 统一字符规范、角色格式和结束标记。保留划分结果，后续实验不要重新随机切分。
5. 当前每个 token 是一个字符。`context=256` 表示 256 个字符，不是 256 个词。统计完整问题、答案、角色标记的总长度，再决定窗口大小。

可选公开来源：[OpenAssistant OASST1 官方数据卡](https://huggingface.co/datasets/OpenAssistant/oasst1)。它有英文、多轮树结构及训练/验证划分，许可证为 Apache-2.0。它不是可以直接喂给当前脚本的扁平问答文件：需要按 `lang`、`role`、`parent_id` 等字段还原关系，筛选有效内容，并按 `message_tree_id` 保持同一对话树不跨集合。不必一开始处理全量数据。

现有 `format_dialogue` 只接受单行问答，真实数据的多段回答需要合理预处理，或后续扩展接口。不要把长答案随意截断后当作完整答案，也不要因窗口太短把问题截掉却还期望模型学会条件回答。

`play7.py` 新增两个参数：

- `--data`：UTF-8 文本。默认仍是 `data/alice.txt`。
- `--val-data`：独立验证文本。省略时按字符位置取前 90% 训练、后 10% 验证，仅适合最初的流程练习。

问答应先按对话切分，再分别格式化为两个文本文件，显式传入两条路径。词表只由训练文本建立；验证文本若出现未知字符，脚本会报错。应对所有集合采用一致的字符规范，或另行设计固定字符表；不要把验证答案复制进训练集来消除报错。微调已有模型时还要检查角色标记在原词表里。

## 3. 从一次短试跑开始

本机检测到 RTX 2060，6 GiB 显存，CUDA 可用。下面是实验起点，不是测得的最优配置，也不是显存保证：

| 命令参数 | 起点 | 你在控制什么 |
| --- | --- | --- |
| `--d-model` | 128 | 每个位置的特征维度；更宽通常参数更多 |
| `--layers` | 4 | 连续进行多少次 Transformer 变换 |
| `--heads` | 4 | 多头注意力的头数；必须整除 d-model |
| `--context` | 256 | 每条训练窗口包含多少字符 |
| `--batch-size` | 8 | 每一步采样多少条窗口 |
| `--lr` | 0.0003 | AdamW 更新幅度的尺度，不是固定的参数位移 |
| `--steps` | 200 | 做多少次 optimizer.step；这里只用于短试跑 |
| `--seed` | 42 | 便于重复实验的随机种子 |

先用仍保留的 Alice 文本练习读取结果。在项目终端自行运行：

```powershell
python play7.py --device cuda --d-model 128 --layers 4 --heads 4 --context 256 --batch-size 8 --lr 0.0003 --steps 200 --seed 42 --new-tokens 160
```

它会从随机权重训练小说续写模型，生成文本并保存 `runs/mini_gpt_时间/`。200 步的用途是确认速度、显存和 loss 是否合理，文字差并不意味着训练失败。当前脚本训练中不实时打印每一步，结束后统一保存 loss。不要因为中间安静就认定程序卡死。

每一步处理 `B × T` 个预测目标。这个配置每步 2048 个字符目标，200 步共 409600 个；窗口是随机抽的，会重复。`steps × B × T / 训练字符数` 只能估算重复暴露量，不表示每个字符恰好看了同样次数。

有自己的文本文件后，命令模板是：

```powershell
python play7.py --data data/train.txt --val-data data/val.txt --prompt "User: " --device cuda --d-model 128 --layers 4 --heads 4 --context 256 --batch-size 8 --lr 0.0003 --steps 200 --seed 42
```

这两个示例路径没有替你创建；已下载数据的实际路径见 `data/dailydialog/README.md`。`User: ` 仅适用于已按该格式整理的问答文本，普通文本换成对应前缀。`play7.py` 的产物可以用 `interact7.py --checkpoint ...` 续写，也可以直接用 `chat7.py --checkpoint ...` 以对话格式生成；不需要先微调。只有决定继续更新权重时才使用 `finetune_chat.py`，后者必须显式指定基础权重和 JSONL 数据，不能传入 `.txt`。

## 4. 先学会看结果

每次保留 `metrics.json`、`sample.txt`、`model.pt`。记录数据版本、配置、耗时、训练 loss、验证 loss 和固定提示的原始输出。训练 loss 看一段的平均值或趋势，别让某一步的波动带着你调参。

交叉熵 loss 是正确下一字符的负对数概率的平均：正确答案获得的概率越高，loss 越低。完全均匀的预测对应 `ln(词表大小)`；随机初始化不一定恰好等于它。不同词表或不同任务的 loss 不宜直接比较。

| 观察 | 可能说明什么 | 下一次实验 |
| --- | --- | --- |
| 训练、验证都下降 | 对未见文本的预测也在改善 | 固定配置，试更长的训练 |
| 训练下降，验证持续上升 | 可能过拟合：越来越记住训练集 | 缩短训练，改善数据多样性，必要时减小模型 |
| 两者都很高且长期不动 | 更新太慢、数据问题或容量不足等 | 先查格式与 loss，再单独测试学习率 |
| loss 出现 NaN/Inf | 数值问题或更新不稳定 | 停止该次实验，查输入/实现，尝试降低学习率 |
| CUDA out of memory | 显存不足 | batch 8→4→2；仍不足再考虑窗口/模型大小 |

这些是排查方向，不是仅凭一条曲线就能确定的诊断。注意力分数张量大小为 `B × H × T × T`，窗口翻倍会使这一部分的内存约增至四倍，别把 context 当免费开关。

**当前工具的限制：** `play7.py` 只在训练前后评估同一个随机验证 batch，没有周期性验证、早停或最佳模型选择。因此它适合初步排错，不足以可靠判断过拟合发生在哪一步。比较同样 B/T 的学习率实验时，同数据同 seed 可保持这个验证 batch 一致；改变 batch 或窗口后，验证采样/协议也变了，不能把数值变化都算成模型进步。

正式比较需要固定验证样本，评估多个 batch 或全验证集，并按有效 token 数加权平均。8A 就是补上这个能力；目前它仍是可选，`eval7.py` 依赖的 8A 函数尚未完成，因此现在不能用它评估，而且该脚本目前只读取 Alice。真实问答还要人工检查未见问题是否答对，低语言模型 loss 不等于事实正确。

## 5. 调参顺序：一次只改一个因素

先固定数据划分、词表、模型、种子、提示和比较预算，再做小规模对照。

1. **确认训练有效。** 短试跑 loss 有限、速度正常；必要时用很小的真实训练子集做过拟合排错，看能否记住它。这种排错不算泛化实验。
2. **学习率优先。** 从 `3e-4` 起，可比较 `1e-4 / 3e-4 / 1e-3`。同模型同数据同预算；看稳定性和验证表现。短跑中下降最快的值未必长期最好，候选再用较长预算确认。微调可从更小的 `1e-4` 试起。
3. **再比较训练时长。** 短跑有效后，例如试 1000 步。是否继续取决于验证改善和耗时，不是“步数越大越好”。当前重复运行 play7 是从头重训，不能当成续接上一次。
4. **有证据再增容量。** 数据够、训练稳定，但训练和验证都难以进一步改善时，再试更宽或更深，例如 C128→192 或 L4→6，分开改。数据很少时先扩大模型往往只会更容易记忆。
5. **窗口按任务长度选，batch 按显存和吞吐选。** 修改它们会改变每步字符数；公平比较要记录总 token 预算，而不能只对齐 steps。初期固定头数 4，不要同时搜索所有参数。

固定种子用于减少比较噪声，不代表某次结果必然可跨设备精确复现。选出候选配置后，可用不同种子确认趋势。不要反复用测试集选参数。

当前训练器是固定学习率 AdamW、`weight_decay=0.01`；没有 warmup、scheduler、梯度累积、梯度裁剪、混合精度或 dropout 开关。先把基础对照实验做清楚，再按实际问题逐项扩展，别在命令里写尚不存在的参数。

temperature 只调整生成时如何选下一个字符。调低它可能更稳定，也可能更重复；它不能修复缺乏知识或没训好的权重。

## 6. 保存权重与续训的区别

当前两个训练入口保存模型配置、词表和权重，用于推理；不保存 AdamW 的历史统计。

- 重跑 `play7.py`：新的随机模型。
- `finetune_chat.py --base ...`：加载已有模型权重，创建新优化器。
- 精确断点续训：还要恢复 optimizer、训练步数，以及用到的 scheduler、随机数状态等。

PyTorch 官方说明了[通用训练 checkpoint 需要保存 optimizer 状态](https://docs.pytorch.org/tutorials/beginner/saving_loading_models)。后续若想中断后继续，我们再把续训功能作为独立任务补齐；不要反复调用当前训练函数分段训练来冒充连续训练，因为每次调用都会重建 AdamW。
